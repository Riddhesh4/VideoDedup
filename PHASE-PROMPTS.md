# VideoDedup — Phase-by-Phase Implementation Prompts

Canonical prompt library adapted from the user-provided architecture-plan PDF and the decisions recorded in [`DECISIONS.md`](DECISIONS.md). The prompt author should send **only the common preamble plus one selected phase prompt** to an implementation agent; do not paste the entire file into every session.

## How to use this file (token-efficient handoff)

1. Start each new session/model by reading only [`.cursor/skills/vibecoding-context/SKILL.md`](.cursor/skills/vibecoding-context/SKILL.md). It contains the repository map, invariants, commands, and current phase. Do not reread every source file or every document by default.
2. Select the next unchecked phase from [`TASKS.md`](TASKS.md). Read [`ARCHITECTURE.md`](ARCHITECTURE.md) and [`DECISIONS.md`](DECISIONS.md) only if the task needs details not in the skill; read [`PLAN-REVIEW.md`](PLAN-REVIEW.md) or this prompt's referenced subsections only when needed.
3. Send the common preamble below plus **one phase prompt**. The agent must inspect only the named/scoped files and their direct dependencies before editing; ask it to report any scope expansion first.
4. A phase is not complete until its Definition of Done is verified, `TASKS.md` and the skill Progress are updated, and changes are committed. Never claim a test/build/packaging check that was not actually run.

## Common preamble (include with every phase prompt)

> You are implementing one bounded phase of VideoDedup. First read `.cursor/skills/vibecoding-context/SKILL.md`, the selected phase prompt, and only the existing files needed for that phase. Follow `ARCHITECTURE.md` and `DECISIONS.md`; these are authoritative. Do not re-scan or regenerate the whole repository. Do not change dependencies, public contracts, architectural boundaries, or decisions outside the phase scope without explaining the need and getting approval. Work tests-first for domain/matching behavior. Keep nullable enabled and warnings as errors. Treat media, filenames, paths, metadata, SQLite contents, and subprocess output as untrusted. Use `ProcessStartInfo.ArgumentList`, never a shell; enforce cancellation, time/resource limits, bounded output, explicit exit-code checks, and safe error reporting. No secrets may be embedded in the client or logged. No automatic permanent deletion; quarantine/undo/last-copy protection remain invariants. No GPL/nonfree binaries; update `THIRD-PARTY.md` when adding an external binary/package. Obfuscation is friction only, not a security boundary. At the end report exact files changed, commands and exit statuses, test coverage, limitations, and any decision needing approval. Do not start the next phase.

## Phase 2 — Scan roots and file discovery

**Scope:** Application discovery interfaces/use case, Infrastructure filesystem/drive adapters, SQLite repository only as required for discovery; DiscoveryWorker may enqueue durable jobs but do not implement the full queue beyond the minimal contract. Local folders and USB drives are v1. Network shares can be represented as a root type but are not scanned by default.

> Implement adding, editing, enabling/disabling, and rescanning local-folder and USB scan roots, with include/exclude patterns and supported video extensions. Discovery creates/updates file records and skips unchanged files. Define stable file identity using volume signature with the documented fallback/tie-breaker from the architecture review; a changed/missing signature with matching path must become reviewable/uncertain rather than silently creating a false identity. Use injectable filesystem/drive/repository interfaces; no UI calls into filesystem directly. **Tests:** fake filesystem unit tests, temporary-directory integration tests, BDD scenarios for add/rescan/unchanged, rename/move, USB letter change, signature mismatch, unavailable root, and symlink loop. **Definition of Done:** no unchanged file is enqueued for processing twice; offline roots retain their records and report unavailable state; enumeration is cancelable and bounded; build/tests/architecture tests pass; no unsafe path traversal or duplicate-root loops.

## Phase 3 — Durable SQLite job queue

**Scope:** Infrastructure queue repository/schema and Application queue contracts; worker-facing interfaces. Avoid implementing FFmpeg or matching work.

> Implement a durable SQLite queue for Discover, Probe, Hash, VisualFingerprint, AudioFingerprint, Match, and Maintenance jobs. Use `Microsoft.Data.Sqlite`; initialize WAL once, enable `foreign_keys` and `busy_timeout >= 5000` for every connection; claim jobs atomically using `BEGIN IMMEDIATE`; serialize mutations through a single-writer discipline while permitting independent reads. Ensure atomic lease/lock acquisition, expired-lease recovery, bounded retry with exponential backoff/jitter, max attempts, poison/dead-letter state, idempotency, cancellation-safe acknowledgements, crash recovery, priority, per-drive/global concurrency limits, and no duplicate active job for `(FileId, JobType)`. Never trust `PayloadJson`; validate versioned payload schemas and size limits. **Tests:** concurrent claims (prove no duplicate claim), unique active jobs, transaction rollback, retry timing deterministically via injected clock, poison jobs, cancellation at each transition, crash/restart simulation, stale leases, malformed/oversized payload, DB busy/locked behavior, migration from empty and prior schema. **Definition of Done:** jobs survive process termination and resume without losing completed work or duplicating active work; test concurrency is repeatable; migration is transactional; no worker can hold a DB transaction while running media processing; all tests/build pass.

## Phase 5 — Visual fingerprints

**Scope:** Frame-sampling policy in Domain/Application; FFmpeg frame extraction and pHash implementation in Infrastructure; VisualFingerprintWorker.

> Implement deterministic video frame sampling by configurable interval/max-frame count, decode sampled frames with FFmpeg into a bounded normalized grayscale buffer, and compute a perceptual hash with a small in-house implementation. Do not add OpenCvSharp/ImageSharp unless a separate, approved decision documents maintenance, runtime, and license impact. Persist frame timestamp, hash, algorithm/version, and quality score. Filter or mark black/near-static/low-quality frames so intros, black screens, and test patterns cannot dominate matching. Handle rotation, variable/low FPS, HDR/10-bit, unusual pixel formats, different aspect ratio/resolution, decoder errors, hardware decode failure (software fallback), short/corrupt/no-frame videos, and excessive duration/frame demand. Enforce pixel, memory, CPU/time, and frame-count bounds. **Tests:** sampling boundaries, deterministic hash outputs, similar hash for re-encoded/resized fixture, different-content separation, black-frame rejection, short/long video, VFR/rotation metadata, 10-bit fallback, decoder failure, cancellation, and version migration. BDD: same video content re-encoded/resized is a near-match candidate, never auto-confirmed solely by one frame. **Definition of Done:** deterministic versioned hashes, bounded resource use, decode failure never creates an exact match, tests/build pass, no new native dependency without decision approval.

## Phase 7 — Matching engine

**Scope:** Pure Domain policy and Application orchestration that combines existing fingerprints; matching worker persistence. No UI/destructive actions.

> Extend `IDuplicateMatchPolicy` to classify exact SHA-256, near duplicate (visual sequence and/or audio evidence), partial clip (sliding-window audio alignment followed by visual confirmation at the offset), and NeedsReview. Support configurable thresholds/weights stored as versioned configuration. Match across all indexed roots/drives. Every result must include explainable signals, component scores, offsets, fingerprint versions, and reasons. Avoid false positives from shared intros/outros, black screens, silence, repeated themes, same audio/different visuals, same visuals/replaced audio, partial overlaps, concatenations, mirrored/cropped content, time shifts, frame-rate conversion, and low-quality re-encodes. Never auto-delete or make an irreversible action. AI embeddings are explicitly out of v1 unless separately approved; no cloud. **Tests:** unit/property tests for score bounds, symmetry where required, deterministic ordering, missing/conflicting signals, threshold edges, and invalid config; sequence alignment tests; generated fixtures for exact, re-encoded, excerpt, unrelated, shared intro, black/silent, replaced audio, multiple clips, and cross-drive matches; BDD for exact, re-encoded near-match, partial clip, ambiguous NeedsReview, and cross-drive duplicate. **Definition of Done:** every match is explainable; no match exists without fingerprint evidence; false-positive regression corpus passes; no automatic delete; all tests/build pass.

## Phase 8 — WPF review UI and safe actions

**Scope:** Desktop presentation/ViewModels, Application review/quarantine use cases, Infrastructure safe filesystem move/undo adapter. Never invoke FFmpeg/SQLite/process directly from UI.

> Build the WPF review flow over application interfaces: duplicate groups, root/drive availability, paths, duration, resolution, codecs, size, visual/audio/overall scores, match type/reason, and side-by-side previews at aligned offsets. Provide Keep, Reject, NeedsReview, and Quarantine states; helpers may recommend newest/highest-quality/original but never perform destructive operations automatically. Quarantine is reversible, collision-safe, same-volume where possible, and has a durable undo log. Permanent deletion is disabled by default and, if ever added, requires explicit separate enablement and confirmation. Prevent quarantining the last remaining copy; warn when actions span physical drives; offline files cannot be acted upon. Show per-worker state, queue depth, progress, pause/resume/cancel, and recoverable errors; ensure accessibility and keyboard navigation. Sanitize/render filenames and paths as text, not markup. **Tests:** ViewModel tests, command enable/disable, last-copy protection, stale/offline state, confirmation, quarantine collisions/partial moves/undo crash recovery, cross-volume move, ACL/access denied, and a11y smoke checks. BDD: review, reject, quarantine/undo, offline drive, last-copy guard, worker pause/resume. **Definition of Done:** no destructive action without explicit user confirmation; undo restores data; offline and unauthorized paths cannot be acted on; WPF packaged Release build (after obfuscation) launches and XAML bindings/views work; tests/build pass.
